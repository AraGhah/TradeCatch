# TC-020 — Complete automatic appointment booking

Verified October 25, 2026. Availability, calendar holds, English/French slot
selection, concurrent reservation, idempotent replay and honest fallback passed
59 focused tests with real isolated PostgreSQL and no skips.

Fixed a failure after booking: an exception while queueing confirmations could
make a saved appointment appear unsuccessful. Confirmed appointments now persist
a pending-notification flag in the same write. Notification queue errors leave
the booking confirmed. The existing scheduling cron retries pending notices in
bounded batches, and replaying the original request also retries them without
creating a second reservation. Existing downstream queues deduplicate notices.
Canceled appointments are excluded and completion updates are scoped by tenant
and appointment time. PostgreSQL tests verify the durable flag and these guards.

Apply the normal schema command before deploying; migration
`060_scheduling_confirmation_recovery` adds the pending flag and its index.
Old appointments default to no pending notices, avoiding historical resends.

Real Twilio calls remain pending at the owner's request. Live Google Calendar
and received SMS confirmation still require controlled pilot verification.
