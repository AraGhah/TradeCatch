# TC-007 — Verify Supabase production security

October 24 status: source review and production database metadata audit completed;
dashboard Data API settings remain pending sign-in. No production writes made.

- All 112 application tables have RLS enabled; no RLS policies are present.
- API roles have effective table privileges on 107 tables, but no BYPASSRLS or
  inherited roles. RLS currently denies ordinary row access. These redundant
  grants and permissive creator defaults remain a hardening action.
- No public views exist. The only public function is `rls_auto_enable`, returning
  `event_trigger`; it is not an ordinary callable RPC for reading application data.
- The application's PostgreSQL role bypasses RLS intentionally. Organization
  isolation depends on signed/stored session binding, current membership, scoped
  queries, and the separate session-specific platform-administrator MFA gate.
- Source installation does not automatically invoke the standalone lockdown.
  Fresh deployments must verify protection rather than assume production state.
