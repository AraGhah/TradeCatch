# TC-009 — Prevent duplicate callback queue collisions

GitHub CI exposed a concurrent duplicate callback race in the existing backup
email recovery path. Its stable delivery ID and organization/idempotency key
both have unique indexes. The targeted conflict handler could still raise a
primary-key violation when simultaneous inserts contested both indexes.

Insert-only delivery saves now use untargeted ON CONFLICT DO NOTHING. Normal
updates retain the existing organization/key and matching-ID guard. Duplicate
callbacks neither reset a sent delivery nor produce a second queued email.

Added a 20-way concurrent insert regression check for memory and PostgreSQL,
including preservation of delivered status. The recovery suite now uses the
existing isolated-schema helper to avoid stale rows across repeat runs.

Validation: all 42 focused recovery and escalation checks passed with PostgreSQL,
with no skips. Changed-file ESLint and formatting passed. Required GitHub checks
remain the merge gate; production deployment is not claimed.
