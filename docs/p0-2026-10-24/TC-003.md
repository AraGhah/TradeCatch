# TC-003 — Recover stuck booking deliveries

Verified October 24, 2026. This task concerns booking notification leases, not the
Stripe subscription task in the older `TC-003_VERIFICATION.md`.

The existing worker claims due jobs with `FOR UPDATE SKIP LOCKED`, records a
two-minute lease and unique token, and reclaims expired leases automatically.
Completion is conditional on the same token so an interrupted worker cannot
overwrite a newer worker's result. The minute scheduler invokes the retry route.

The 32-test booking notification suite passed against isolated PostgreSQL 17 on
October 24, with no failures or skips. Its real database tests verified concurrent
claims, abandoned lease recovery, and stale-worker fencing. Successful channels
remain excluded from subsequent claims. No implementation change was needed.

These are local runtime/database checks. The current production scheduler was
not reconfigured or independently exercised in this verification.
