# TC-006 — Correct escalation delivery status

Escalation history now derives from the durable delivery record in both memory
and PostgreSQL. Queue insertion reports `backup_queued`, provider acceptance
reports `backup_submitted`, and only confirmed delivery reports `backup_notified`.
Terminal failure, cancellation, and simulation have separate outcomes. Old
queue-time `backup_notified` audit entries cannot override delivery state.

The delivery also serves as the escalation attempt record, eliminating the crash
gap between queuing a delivery and recording the attempt. Retries and provider
callbacks update that same authoritative state. Duplicate/out-of-order callbacks
cannot regress a confirmed SMS delivery. Email remains submitted because this
notification pipeline has no confirmed-email-delivery callback.

October 24 validation: eight regression cases passed across memory and isolated
PostgreSQL, with no skips. Full unit suite: 845 passed, zero failed, two optional
integration checks skipped. Production Next.js build and changed-file lint passed.
No schema migration is required.
