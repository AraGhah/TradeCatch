# TC-005 — Fix backup escalation skipping

An unacknowledged urgent alert now escalates even when the selected backup already
received the initial notification. The existing recipient is preserved, including
read state. A unique delivery key prevents concurrent workers from queuing the
same escalation twice. Further escalation attempts honor the configured delay
and maximum count; any acknowledgment still stops escalation.

October 24 validation: four regression tests passed in memory and isolated
PostgreSQL, with no skips. They exercise existing recipients, concurrent workers,
read-state preservation, spacing, attempt limits, and acknowledgment. Production
Next.js build and changed-file ESLint passed.

Delivery-status wording is addressed separately by TC-006.
