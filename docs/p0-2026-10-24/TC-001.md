# TC-001 — Prevent lost leads

Verified on October 24, 2026 against the current repository.

The booking endpoint requires configured PostgreSQL before consuming a verification
token. It confirms acceptance only after the lead, native sales record, and outbox
commit together. Missing storage, rejected writes, and empty save results return
503. Notification failures after persistence retain the saved lead.

Validation: `node --import tsx --test tests/unit/book-audit-durability.test.ts`:
23 passed, zero failed or skipped. Covers disabled/missing storage, failed writes,
concurrent failed duplicates, retry with the same key, untrusted Redis duplicate
claims, and saved-but-undelivered responses.

No implementation change was necessary. This is fresh local verification, not a
new production deployment or a fresh live production acceptance test.
